#+title: mmux
#+author: Brett Viren

Monitor tmux sessions on remote (and local) hosts in a Textual TUI.
Events flow through a filesystem queue (~mmuxq~) on each remote host and
are streamed to the local machine over SSH.

* Installation

#+begin_src shell
uv tool install mmux
mmux install user@host
mmux tui user@host
#+end_src

* TUI Key Bindings

| Key      | Action             |
|----------+--------------------|
| ~q~      | Quit               |
| ~r~      | Reconnect all      |
| ~a~      | Add remote target  |
| ~n~      | New tmux session   |
| ~s~      | Save config        |
| ~l~      | Toggle log panel   |
| ~enter~  | Attach to session  |
| ~tab~    | Toggle expand node |
| ~j~/~↓~  | Cursor down        |
| ~k~/~↑~  | Cursor up          |

Pressing ~s~ writes the currently monitored remotes (and all other
settings) back to the active configuration file.  If the file does not
yet exist it is created automatically.

* Configuration

The default configuration file is:

#+begin_example
~/.config/mmux/config.toml
#+end_example

Override this with the ~--config PATH~ global flag:

#+begin_src shell
mmux --config /path/to/my.toml tui
#+end_src

** Schema

#+begin_src toml
[defaults]
# Seconds after the last keystroke before a pane turns yellow (◎).
active_secs = 30

# Seconds after going yellow before a pane turns white (○).
silent_secs = 300

# Base directory for mmux state on every remote host.
queue_path = "~/.local/state/mmux"

# One [[targets]] block per remote host to monitor.
[[targets]]
# SSH destination accepted by the system ssh(1) binary.
# Examples: "user@host", "host", "alias-from-~/.ssh/config"
host = "user@hostname"

# Optional list of tmux session names to display.
# When empty all sessions on the host are shown.
sessions = []
#+end_src

*** Field reference

**** ~[defaults]~ table

| Field         | Type    | Default                   | Description                                         |
|---------------+---------+---------------------------+-----------------------------------------------------|
| ~active_secs~ | integer | ~30~                      | Seconds of activity before a pane turns yellow (◎) |
| ~silent_secs~ | integer | ~300~                     | Seconds silent before a pane turns white (○)        |
| ~queue_path~  | string  | ~"~/.local/state/mmux"~   | Base state directory on remote hosts                |

**** ~[[targets]]~ array of tables

Each entry describes one host to monitor.  You may have any number of
~[[targets]]~ blocks.

| Field      | Type            | Required | Description                                              |
|------------+-----------------+----------+----------------------------------------------------------|
| ~host~     | string          | yes      | SSH destination (~user@host~, hostname, or SSH alias)    |
| ~sessions~ | array of strings | no      | Session names to show; empty means show all sessions     |

** Example

#+begin_src toml
[defaults]
active_secs = 60
silent_secs  = 600
queue_path   = "~/.local/state/mmux"

[[targets]]
host = "dev-server"

[[targets]]
host = "user@build-box"
sessions = ["main", "ci"]
#+end_src

* Container Support

mmux can monitor Claude running inside a podman or docker container on a
remote host (or locally).  Events are routed through a shared volume that
bridges the container's hook output to the host's ~mmuxq~ dispatcher.

** How it works

The container's user home directory lives on a named volume.  A second
volume (or a bind-mount of the host's mmuxq claude PMP directory) is
mounted inside the container so that the ~mmux-claude-hook~ script can
drop event files directly into the host's queue.

#+begin_example
container
  ~/.claude/settings.json   ← written by priming; calls mmux-claude-hook
  ~/.local/bin/mmux-claude-hook
  ~/.local/state/mmux/claude.pmp → /run/mmux/pmp  (the PMP mount)

  /run/mmux/pmp/            ← bind-mount of host PMP directory
       └── <event files>    ← hook writes here; host dispatcher picks up
#+end_example

** Two-phase setup

*** Phase 1 — prime the home volume (once per image/volume combination)

#+begin_src shell
mmux container hooks --name <image> --nick <nick> [REMOTE ...]
#+end_src

where ~<nick>~ refers to a ~[container.<nick>]~ section in ~config.toml~ that
supplies ~home_volume~ and ~home_mount~.  Alternatively pass them on the
command line:

#+begin_src shell
mmux container hooks --name <image> --home-volume <vol> --home-mount <path> [REMOTE ...]
#+end_src

This runs a short-lived container as root that:

1. Creates ~<mount>/.local/bin/mmux-claude-hook~
2. Writes ~<mount>/.local/state/mmux/claude.pmp~ pointing to the PMP mount
3. Merges the ~Notification~ hook entry into ~<mount>/.claude/settings.json~

The PMP volume does *not* need to be present during priming — only the home
volume is required.

After a successful prime the command prints the exact ~-v~ flags to add to
every real container run, for example:

#+begin_example
Done. Add to production container runs:
  -v mmux-claude-auth:/home/user
  -v /home/bv/.local/state/mmux/queue/producers/0002/queue:/run/mmux/pmp:Z
#+end_example

*** Phase 2 — run the container normally

Add the two volume flags (shown above) to your usual ~podman run~ / ~docker
run~ invocation:

#+begin_src shell
podman run --rm \
  -v mmux-claude-auth:/home/user \
  -v /home/bv/.local/state/mmux/queue/producers/0002/queue:/run/mmux/pmp:Z \
  <other flags> \
  <image> \
  <command>
#+end_src

The ~:Z~ suffix is required for SELinux-enabled systems (default on Fedora /
RHEL); omit it for Docker or non-SELinux hosts.

** Prerequisites

- ~mmux install [REMOTE]~ must be run first so the host's mmuxq queue and
  claude producer are provisioned (the ~claude.pmp~ path must exist).
- The container image must include ~bash~, ~python3~, and ~base64~.

** CLI reference

*** ~mmux container list~

Print configured ~[container.*]~ sections (one line each, resolved values):

#+begin_src
$ mmux container list
default   podman  -                      /run/mmux/pmp
myapp     podman  myapp-home:/home/user  /run/mmux/pmp
otherapp  docker  other-home:/home/other /run/mmux/pmp
#+end_src

Columns show the /resolved/ values (nick-specific merged over default).

*** ~mmux container run NICK [ARGS...]~

Run a container with the mmux volume mounts automatically injected.
Given this config:

#+begin_src toml
[container.myapp]
home_volume = "myapp-home"
home_mount  = "/home/user"
run_args    = "--rm -ti"
image       = "myimage"
#+end_src

the command:

#+begin_src shell
mmux container run myapp bash
#+end_src

expands to:

#+begin_src shell
podman run \
  -v myapp-home:/home/user \
  -v /home/bv/.local/state/mmux/queue/producers/0002/queue:/run/mmux/pmp:Z \
  --rm -ti \
  myimage bash
#+end_src

The full expansion order is: mmux volume flags, ~run_args~ tokens, ~image~
(if set), then any extra arguments supplied on the command line.  If ~image~
is not set the user must supply the image name as the first extra argument.  The PMP path is read from
the local ~claude.pmp~ file (provisioned by ~mmux install localhost~).  If
it is not yet provisioned a warning is printed and only the home volume is
mounted.  The full command is logged at DEBUG level to the mmux log file.

*** ~mmux container hooks~

#+begin_src
mmux container hooks [OPTIONS] [REMOTE ...]

  --name CONTAINER        Container name or image (required)
  --nick NICK             Config nickname: uses [container.<nick>] (default: default)
  --home-volume VOLUME    Home volume name (overrides config)
  --home-mount  MOUNT     Home volume mount path inside container (overrides config)
  --client [podman|docker]
                          Container runtime (default: podman)
  --pmp MOUNT             PMP mount point inside container
                          (default: /run/mmux/pmp)
#+end_src

** Configuration

Container settings live in independent ~[container.<nick>]~ sections.
~[container.default]~ provides base values inherited by every nickname.
This lets different containers share defaults while overriding individual
fields, and decouples container config from the ~[[targets]]~ host list.

#+begin_src toml
[container.default]
client      = "podman"
pmp_mount   = "/run/mmux/pmp"
run_args    = "--rm"

[container.myapp]
home_volume = "myapp-home"
home_mount  = "/home/user"
run_args    = "--rm -ti"        # overrides default for this nickname

[container.otherapp]
home_volume = "other-home"
home_mount  = "/home/other"
client      = "docker"
#+end_src

Select a nickname with ~--nick~; omitting ~--nick~ uses ~"default"~.

*** Container field reference

Each ~[container.<nick>]~ section supports:

| Field          | Type   | Default           | Description                              |
|----------------+--------+-------------------+------------------------------------------|
| ~client~       | string | ~"podman"~        | Container runtime (~podman~ or ~docker~) |
| ~pmp_mount~    | string | ~"/run/mmux/pmp"~ | PMP mount point inside the container    |
| ~home_volume~  | string | —                 | Volume name for the container user home  |
| ~home_mount~   | string | —                 | Mount path of ~home_volume~ in container |
| ~run_args~     | string | ~""~              | Extra flags inserted before the image in ~container run~ |
| ~image~        | string | ~""~              | Container image name, inserted after ~run_args~          |

~home_volume~ and ~home_mount~ are required (from config or CLI flags) for
~mmux container hooks~ and ~mmux container run~ to work.

~run_args~ is passed as a raw shell fragment, so shell expansions such as
~$(pwd)~ and ~$HOME~ are evaluated at run time.  The mmux-generated parts
(volume flags, image name, command-line arguments) are properly quoted
before being combined with ~run_args~ into the final shell command.

* Status Indicators

Each pane is annotated with a coloured dot:

| Symbol | Colour | Meaning                                           |
|--------+--------+---------------------------------------------------|
| ~●~    | green  | Activity within the last ~active_secs~ seconds    |
| ~◎~    | yellow | Gone silent, or no activity for 30–300 s          |
| ~○~    | white  | No activity for more than ~silent_secs~ seconds   |
